# ADR 0001: AI 컨텍스트 문서 체계 (AGENTS.md SSOT, L1/L2, 자동 검사)

- 상태: 채택
- 날짜: 2026-10-25
- 참조: d94-web ADR 0001~0003 (같은 체계를 프론트엔드에 먼저 적용)

## 배경
- AGENTS.md/CLAUDE.md 가 없어 어떤 AI 도구도 UMD 컨텍스트를 자동으로 받지 못했습니다.
- 현재 상태 문서(아키텍처, 연동 가이드)가 이력 폴더 `note/` 에 섞여 있었고, 같은 폴더에 폐기된 설계(eventNm 게이트웨이, lib-core 규격)가 남아 있었습니다.
- 셸에서 빌드할 수단(Maven Wrapper)이 없어 AI 가 변경을 검증할 수 없었고, Docker 가 없으면 통합 테스트가 조용히 skip 됩니다.

## 결정
1. 루트 `AGENTS.md` 를 단일 기준(L1)으로, 도구별 파일은 포인터만 둡니다 (`CLAUDE.md` = `@AGENTS.md`).
2. 계층은 **L1 프로젝트 + L2 패키지**(`common`, `server`, `local`, test)만 둡니다. 화면이 없으므로 d94-web 의 L3/L4 대신 L2 의 `## 흐름` 섹션을 씁니다.
3. d94-web 의 컴포넌트 카탈로그 자리에 **불변식(L1 §5)** 을 둡니다. UMD 에서 AI 가 가장 깨기 쉬운 것은 재사용이 아니라 투명성·신뢰성 규칙입니다.
4. **현재 상태는 `docs/`, 이력은 `note/`** 로 나누고, `note/` 는 기본 로드 대상에서 뺍니다. 이력 본문은 고치지 않고 `note/README.md` 에 바뀐 사실만 적습니다.
5. 동기화 검사는 Node 스크립트가 아니라 **JUnit `ContextDocsTest`** 로 하고, 위반하면 **빌드를 실패**시킵니다.
   - d94-web(연습장)은 커밋이 막히는 비용 때문에 차단하지 않았지만, UMD 는 배포되는 인프라이고 문서가 운영 계약(오류 코드·설정·지표·환경 변수)을 겸하며 문서 표면이 작아 차단 비용이 낮습니다.
   - CI(`mvn verify`)에서 추가 설정 없이 실행됩니다.
6. Maven Wrapper(`./mvnw`)를 추가해 셸에서 검증 가능하게 합니다.

## 결과
- 클래스·오류 코드·설정·지표·환경 변수를 바꾸면 같은 커밋에서 문서도 바꿔야 빌드가 통과합니다.
- 설명의 정확성은 검사하지 못합니다. L1 §10 매핑표를 따르는 책임은 작업자에게 있습니다.
- 문서 구조를 바꾸면(예: architecture 의 절 구성) `ContextDocsTest` 의 기준도 함께 고쳐야 합니다.
